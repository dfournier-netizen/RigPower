# Routing verification

The application has no build step. These optional development checks need Node.js; the browser suite also needs Playwright and Chrome. Set `NODE_PATH` to your installed package directory, or `RIGPOWER_PLAYWRIGHT` to the Playwright package. `RIGPOWER_BROWSER` can select another installed Playwright browser channel.

From the repository root:

```text
node tests/engine_test.cjs <new-build.html>
node tests/verify-routing.cjs <new-build.html>
node tests/verify-combined.cjs <new-build.html>
node tests/verify-stock-origins.cjs <new-build.html>
```

The routing suite automatically finds its September 21 baseline in the root or `_to_delete/`. The combined suite verifies real project Save/Load, live footprints, circuit assignment, and resulting routing together. The engine suite isolates routing functions and uses a stub stock builder. The browser suite loads the real app, Three.js r128, and stock solver, compares no-path output against the preserved baseline, and exercises routing and renderer integration. Network access to the app's CDN dependencies is required. Browser launch may require appropriate local permissions.

For syntax checking, extract the inline application script (the script without a `src` attribute) to a temporary JavaScript file and run `node --check` on it.

`tools/engine_patch.py` and `tools/render_patch.py` preserve the scoped changes as unique-anchor transformations for review and later integration. Apply engine first, renderer second, with distinct input/output files. They target the September 21 baseline; do not blindly apply them to another branch. The current combined build was generated by applying these transformations to `RIGPOWER_2026-09-22_233803.html`.
